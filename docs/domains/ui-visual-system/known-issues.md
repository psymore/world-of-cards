# UI Visual System — Known Issues

**Owner:** whoever finds/confirms an issue here. **Load:** starting new work on shared visual components. Entries are deleted, not marked "done," once fixed.

---

### Theme color duplication

**Partially resolved, not closed.** `TableWoodCorners`, `TableEdgeRails`, `HeaderWoodFrame`, and `PlatformWoodBackground` no longer duplicate — all four already read their wood gradient/trim/grain values from `packages/ui/src/woodPalette.ts`, which its own header comment states is the single source of truth for that recipe. Two UI visual-theme refinement passes additionally: moved `PistiTable`'s banner text and `PlayerAvatar`'s accent-ring colors from hardcoded `#ffd966` copies to importing `WOOD_TRIM_COLOR` directly; replaced `DecisionPanel`'s hand-decomposed `rgba(255, 217, 102, 0.85)` with a string derived from that same import; and aligned `HomeScreen`'s `BaizeStrip` accent gradient to the actual in-game table green (`#0b6623`, already shared identically by `PistiScreen` and `BatakScreen`) rather than its own separately-chosen dark green (`BaizeStrip` itself was later deleted entirely on 2026-08-07, when HomeScreen moved to sharing `TableFelt` directly — see `docs/superpowers/specs/2026-08-07-home-setup-emerald-felt-design.md`).

Still duplicated, not centralized: `HomeScreen.tsx`, `PistiSetupView.tsx`, `BatakSetupView.tsx`, and related Home/setup-screen files each hardcode their own gold (`#f4c542`) and background/text literals rather than reading from a shared module — and that gold itself has never been reconciled with `WOOD_TRIM_COLOR` (`#ffd966`), the separate gold used by the wood-decoration components. Reconciling those two golds was deliberately left out of both refinement passes: `#f4c542` is the dominant, already-internally-consistent identity across Home, both setup screens, both game-screen titles, and Batak's kitty-exchange UI, so folding it into the wood-trim gold would be a visible, judgment-laden recolor of the app's primary accent, not a mechanical de-duplication. A full navy/gold theme-extraction pass remains repeatedly flagged as worth doing but deliberately deferred each time as a bigger, more foundational decision than whichever cleanup pass surfaces it — this entry stays open until that pass, or an equivalent one, actually centralizes the remaining literals.

### No in-app rules or onboarding for any game

Confirmed 2026-09-04 via `grep -r "onboarding|tutorial|firstLaunch|first-time|walkthrough" apps/mobile/src` — zero matches. `HomeScreen.tsx` (`apps/mobile/src/screens/HomeScreen.tsx:13-42`) goes straight from `GameMenuRow` to `onSelectGame` with no rules screen, "how to play" affordance, or first-launch flow anywhere in that chain, for any of the three built games (Pişti, Batak, Pis Yedili). A player who doesn't already know a game's rules has no in-app way to learn them — this is a genuine gap against Nielsen's heuristic #10 (help and documentation) and #6 (recognition rather than recall), not a stylistic nitpick: Batak in particular (bidding, trump suit, gömmeli) is not a game most players already know cold.

Not yet decided or spec'd. Cheapest plausible shape: a single static "Nasıl Oynanır?" rules-summary screen per game, reachable from `GameMenuRow` or each game's setup screen — `GameMenuRow` already carries per-game metadata (`displayName`, `category`, `minPlayers`, `maxPlayers`) a rules screen could sit alongside. See `docs/superpowers/specs/2026-09-04-ux-monetization-research-backlog.md` for the research this finding came out of.

### Settings icon asymmetry

The global "Dim Unplayable Cards" setting (`apps/mobile/src/state/settingsStore.ts`) only has a gear/settings button to toggle it on Batak's screen (`GameScreenLayout`'s `onSettingsPress` prop, wired only for Batak). Pişti's screen doesn't pass that prop, so it has no way to reach the setting at all — meaning toggling it off in Batak also silently affects Pişti's rendering for the rest of that app session, with no way to restore it from Pişti's own UI. Accepted as-is at the time it was found, but re-flagged here as an open asymmetry — this was intended to be resolved by the "cross-table visual consistency pass" UI-review sub-project, but that pass's 2026-08-07 resolution (see `docs/superpowers/specs/2026-08-07-home-setup-emerald-felt-design.md`) was scoped to Home/Setup backgrounds only and explicitly left this asymmetry open — still unowned, see `docs/status/roadmap.md`.
